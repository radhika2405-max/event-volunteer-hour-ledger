EVENT VOLUNTEER HOUR LEDGER

A Relational Database Management System for Service Hour Accounting, Faculty Verification & Certificate Governance
Author: Radhika (and Team) • Student Organization: ADIKALA (Dance, Emcee, Technical, Creative, Music, Hospitality Sub-Clubs) • Live URL: radhika2405-max.github.io/event-volunteer-hour-ledger • Tech Stack: MySQL 8.0 (3NF/BCNF) • React 18 (Vite, TS) • Flask REST API
1 Real-World Domain & Spreadsheet Crisis

Institutional Context: ADIKALA coordinates student leadership across 6 campus sub-clubs. Co-hosting major university festivals like SUNERGOS and TARANG mobilizes hundreds of volunteer labor hours across setup, stage, and hospitality.

The 4 Fatal Flaws of Traditional Spreadsheets:

  • Mutable Update Anomaly: Storing a single editable "Total Hours" cell causes lost updates when multiple coordinators edit simultaneously.
  • Multi-Club Join Inflation: Co-hosted events associate multiple sub-clubs; unnormalized queries multiply volunteer hours by the club count.
  • Premature Certification: Students with pending unreviewed timesheets claim certificates before faculty verification.
  • Lack of Change Data Capture: Zero auditability of who modified, approved, or revoked hours.
2 The Architectural Solution: The Ledger Paradigm

To eliminate the mutable aggregate anomaly, the schema applies the Ledger Paradigm inspired by financial accounting:

-- Total hours are NEVER stored as a mutable column! -- Dynamically aggregated via authoritative SQL views: SELECT student_id, ROUND(SUM(verified_minutes) / 60.0, 2) AS approved_hours FROM volunteer_hour_entries WHERE submission_status IN ('approved', 'corrected') GROUP BY student_id;

Status Isolation: Pending claimed hours and rejected submissions are strictly isolated from certified totals, preventing premature rewards.

3 University Milestone Rule & Scope

The 20-Hour Rule: Students achieving ≥ 20 verified volunteer hours (1,200 minutes) across university events earn an official Certificate of Volunteer Contribution.

  • Engineer a 3NF/BCNF relational database schema in MySQL 8.0.
  • Enforce database-level Check Constraints and Foreign Key actions.
  • Implement triggers for workflow state machines and audit logging.
  • Wrap certificate issuance in ACID transactions with row-level locks.
4 Relational Architecture & 10 Tables

The system employs a decoupled 3-tier architecture: React 18 Frontend → Python Flask REST API → MySQL 8.0 InnoDB Engine.

Relation Keys Purpose & Cardinality
users user_id (PK) 1:1 with students; login credentials & RBAC.
students student_id (PK) Academic registry; reg number & programme.
clubs club_id (PK) 1:N Recursive Self-Join (ADIKALA & 6 sub-clubs).
events event_id (PK) 1:N with participation; campus event logs.
event_subclubs (event_id, club_id) M:N junction connecting events to sub-clubs.
event_volunteers participation_id M:N associative entity; UNIQUE (event, student).
hour_entries hour_entry_id 1:N transactional ledger of work intervals.
policies policy_id (PK) Threshold policies (1,200 mins = 20 hrs).
certificates certificate_id Immutable award snapshot + SHA-256 token.
audit_logs audit_id (PK) Change Data Capture before/after JSON states.
5 Normalization (3NF) & Join Inflation

Normalization Decomposition (1NF → 3NF/BCNF):

  • 1NF: Atomic attributes. Decomposed repeating multi-club strings into junction table event_subclubs(event_id, club_id).
  • 2NF: Removed partial dependencies. Non-key club attributes reside in clubs; event attributes reside in events.
  • 3NF & BCNF: Removed transitive dependencies. Separated authentication identity from student records; removed mutable derived totals.

Solving Join Inflation: When an event has 3 sub-clubs, joining clubs directly to hours triples recorded hours! Our design attaches hours strictly to event_volunteers(participation_id), guaranteeing mathematical precision.

6 5 Specialized Database Views
  • vw_student_approved_hours: Canonical student aggregation using SUM(CASE WHEN...).
  • vw_certificate_eligibility: Real-time threshold evaluation separating eligibility from issuance.
  • vw_event_volunteer_summary: Headcount and verified labor per event without duplicate club rows.
  • vw_subclub_contribution_summary: Hierarchy-aware labor analytics for Dance, Emcee, Technical, Creative, Music, Hospitality.
  • vw_pending_review_queue: Actionable queue for faculty approvers.
7 Active Triggers & ACID Concurrency

Active Database Triggers:

  • trg_vhe_before_insert: Validates positive claimed minutes and non-negative breaks.
  • trg_vhe_before_update: Rejection without written notes raises SIGNAL SQLSTATE '45000'.
  • trg_vhe_after_update: Automatically logs old & new states into audit_logs as JSON.

ACID Stored Procedure (Row-Level Locking):

START TRANSACTION; SELECT * FROM policies WHERE policy_id = 1 FOR SHARE; SELECT * FROM students WHERE student_id = 4 FOR UPDATE; -- If approved_minutes < 1200 THEN ROLLBACK; END IF; -- If already issued THEN ROLLBACK; END IF; INSERT INTO certificates (...) VALUES (...); COMMIT;

Prevents duplicate certificate issuance during concurrent requests.

8 B-Tree Indexing Strategy & Analytics

Indexing: Clustered PKs, secondary B-trees (reg_no, email, token), and composite B-tree idx_vhe_part_status(participation_id, submission_status).

Performance: EXPLAIN analysis proves queries use index seeks (ref/range) under 50ms, eliminating table scans (ALL).
